# Offline document scanner SDK

The files feature consumes the versioned [Open Android Doc Scanner](https://github.com/phillip9933/open-android-doc-scanner) Compose SDK. It is pinned to release `v1.1.0` / source commit `e955add9eb6c24df588952245366b43ce521590c` and uses the published coordinate `dev.offlinescan:scanner-ui-compose:1.1.0`. Gradle resolves the SDK's five `dev.offlinescan` modules and their declared dependencies from the release's Maven repository archive; the repository is scoped to that group in `settings.gradle.kts`.

Before building locally, run this from the Android project root (`apps/android`). It works with Python 3 on Windows, macOS, and Linux:

```shell
python scripts/install_offline_scanner_sdk.py
```

The installer release version, URL, source commit, and SHA-256 are recorded in `scripts/offline-scanner-sdk.lock.json`. The 1.1.0 Maven ZIP has SHA-256 `caa07accbd07328f0e4066d3d9c5fce85b479a4da97fd7f246f1f2426ab2ad82`. The installer downloads the archive, verifies its SHA-256 before extraction, rejects unsafe ZIP paths and symbolic links, and checks an existing Maven cache against every packaged repository file. It extracts the `maven/` directory under the ignored `.gradle/open-android-doc-scanner-1.1.0/` cache. Both GitHub Actions workflows install this dependency before running Gradle. See the root [README](../README.md) for the overall build and [Testing](TESTING.md) for verification commands. This page owns the scanner-specific setup.

The SDK release documents Android API 26 or newer and arm64-v8a or x86_64. Raiun builds from current source require API 31 or newer. The published OpenCV AAR contains `libopencv_java4.so` and `libc++_shared.so` for arm64-v8a and x86_64 only, so 32-bit-only devices are unsupported for this dependency. Keep the release archive's license and third-party notice files available when redistributing the SDK; they are included in the downloaded archive.

The scanner processes documents on-device and its release states that it does not require Play services or a model download. Its setup does not add an Internet permission. The SDK's attribution and third-party notices are available in the [pinned release license](https://github.com/phillip9933/open-android-doc-scanner/blob/v1.1.0/LICENSE), [NOTICE](https://github.com/phillip9933/open-android-doc-scanner/blob/v1.1.0/NOTICE), and [third-party notices](https://github.com/phillip9933/open-android-doc-scanner/blob/v1.1.0/THIRD-PARTY-NOTICES.md). The copies bundled in this app come from the verified Maven ZIP. Keep these notices available when redistributing the SDK. Review the final merged manifest and full dependency graph as part of app-level acceptance.

## Upgrading and host behavior

Update `offlineScanner` in `gradle/libs.versions.toml`, the repository version path in `settings.gradle.kts`, and `scripts/offline-scanner-sdk.lock.json` together for a reviewed published release; rerun the installer and host validation. Update the bundled attribution in `app/src/main/assets/third-party/open-android-doc-scanner` if the release changes it. Do not copy the scanner implementation or include its source checkout in this build.

Scan in the shared FAB menu opens the library flow using the app theme. Save chooses PDF or JPEG and the output name; the result enters the normal upload queue for the account/space/folder captured when scanning began. Existing upload conflicts and retry controls apply. Raiun journals committed outputs in private no-backup storage until the upload queue has durably staged them. Active unexported capture pages retain the SDK's documented process-death limitation. The user accepted basic Pixel scanning and destination selection for the initial beta. Broader permission-denial, multipage, cancellation and background/lock edge cases are not certified.

The SDK exposes a generic optional saveDestination Compose slot. Raiun supplies a clickable Location in OpenCloud button, initialized to the exact account, space and folder captured when Scan is tapped. Its folder picker stays within that account and supports changing between Personal and active Spaces. Cancelling leaves the saved location unchanged; choosing persists it before export while the scanner remains mounted. The control is disabled during export, and committed outputs cannot be retargeted. The standalone library still defaults to On this device. No scanner source is copied into Raiun.

Version 0.7.0 raises the default render limits to 8192 pixels per edge and 24 MP, subject to a configurable 384 MB working-memory estimate. Its PDF exporter streams processed pages and preserves each page's resolution budget. These are SDK defaults, not an app-level promise that every device can process that size. `ScanConfig` adds `maxRenderPixels` and `maxWorkingBytes`; `ScannerFlow` and `AndroidExporter` add optional `includeDiagnostics=false`. If a host opts in, `ScanOutput.diagnostics` retains original copies and rendered files that the host must manage and delete with its output. Recompile host consumers for the new Kotlin parameters and data-class fields; positional `ScannerFlow` callbacks may need a named `onResult`. The public-folder export and last-result viewer described in the scanner release are sample-app features, not automatic Raiun behavior. The 0.7.0 release reports no native-library, model-weight, or runtime dependency change, and Raiun host integration checks are recorded in [Testing](TESTING.md#scanner-070-combined-integration-candidate). Physical camera, arm64 and 16 KB-page device acceptance remain separate checks.

## Scanner 1.0.0 integration candidate — 20 November 2026

The five consumed scanner modules use 1.0.0. OCR remains optional and is not added to Raiun; no language models or OCR native libraries are enabled. The public processing AAR still contains the exact unpatched OpenCV binaries from 0.8.0-beta.1. The version-bound Gradle substitution therefore uses `app.raiun.vendor:scanner-processing-opencv:1.0.0-raiun-native.1`. It preserves all new 1.0.0 Java/classes and every other upstream entry except the two `libopencv_java4.so` payloads, which are copied byte-for-byte from the reviewed local native backport. Keeping the old processing substitute would discard the new Java behavior; using the public native bytes would discard the typed-split fix. See [the per-entry repackaging record](../third_party/native-security-fixes/provenance/scanner-1.0.0-repackaging.json) and [native dependency scope](NATIVE-DEPENDENCIES.md).

Version 1.0.0 adds AI-first detection with bounded Standard edge fallback, mirrored-orientation consistency, cancellation-safe destination handling, fresh sessions when host configuration changes, and preview/provider-transfer resource limits. Raiun's existing `ScannerFlow` call remains source-compatible and keeps its account-bound save destination and `includeDiagnostics=false`. `OcrConfig` gained a working-memory budget; consumers using OCR must recompile, but Raiun does not use that API. External dependency versions declared by the five consumed modules are unchanged from 0.8.0-beta.1.

Static archive/API and per-entry checks do not establish physical camera, arm64, OCR, or live upload acceptance. The November 6 sanitizer/native evidence applies to the identical preserved native bytes; current host/build/native integration results must be recorded separately.

## Scanner 1.1.0 integration candidate — 20 November 2026

All five consumed modules now use scanner 1.1.0, source `e955add9eb6c24df588952245366b43ce521590c`. The published release improves immediate page-edge fallback, full-card borders and still-image corner refinement, and carries the captured crop into review. Auto processing preserves two-tone card backgrounds and applies gentler paper processing for faint writing, pencil, highlighter and grids. These are upstream behavior changes, not a claim of fresh handheld-camera acceptance.

Raiun continues to use the ready-made `ScannerFlow`, so no custom camera adapter is required. Account-bound destination selection, private output journaling and diagnostics-off behavior remain unchanged. OCR remains disabled. Declared external dependency versions are unchanged from 1.0.0.

The upstream processing AAR changes `classes.jar` while retaining its previous native libraries. The new `app.raiun.vendor:scanner-processing-opencv:1.1.0-raiun-native.1` coordinate preserves all 1.1.0 payloads except the two reviewed OpenCV library replacements. See [the source-bound repackaging proof](../third_party/native-security-fixes/provenance/scanner-1.1.0-repackaging.json). Older1.0.0 bundles and test evidence remain preserved; new host and packaged integration results are recorded separately in Testing.
